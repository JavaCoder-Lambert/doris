# 4.1.4 NULL-safe Join 修复与交付记录

核查日期：2026-09-11。源码目录 `doris-4.1.4-nullsafe`，分支 `codex/4.1.4-null-safe-join-fix`。本文记录本 fork 的修复；原版发行包对照见 [验证记录](null-safe-join-validation.md)，跨版本升级条件见 [升级评估](4.1.4-upgrade-notes.md)。

## 已提交的修复

基线为官方 4.1.4 的 `ad35a140c7fd0b842f18c23300bac581f7d04326`，修复提交为 [`523e9146c1ffd305edae46bb1bbbf3546d248163`](https://github.com/JavaCoder-Lambert/doris/commit/523e9146c1ffd305edae46bb1bbbf3546d248163)。它按 4.1.4 现有实现回补上游 [#65975](https://github.com/apache/doris/pull/65975) 的必要 BE 变更，没有整段替换 master 的实现。

`ColumnNullable` 用 null map 表示 SQL NULL，其内部字符串列仍可能保留非空字节。原版单字符串 Hash Join 的 key 生成没有使用调用方传入的 null map，导致 NULL 行带着残留字节进入查找，错过应有的 NULL 匹配。修复在 build/probe 两侧把 NULL 行规范为默认 `StringRef()`；真正的空字符串仍按原有 NULL 标记和哈希表逻辑区分。

| 文件 | 变更 |
|---|---|
| [hash_map_context.h](../../be/src/exec/common/hash_table/hash_map_context.h) | 将外部 null map 传入 `MethodStringNoCache::init_serialized_keys_impl`，规范 NULL 行；保留 4.1.4 聚合的 `_sub_table_groups` 行为 |
| [string_ref.h](../../be/src/core/string_ref.h) | 长度为零时直接判断相等，避免将默认空引用的空指针传入 `memcmp` |
| [hash_table_method_test.cpp](../../be/test/exec/hash_map/hash_table_method_test.cpp) | 覆盖 String32/String64、build/probe、nullable 包装/嵌套输入、NULL/空串区分、输入不被修改及聚合路径 |
| [string_value_test.cpp](../../be/test/runtime/string_value_test.cpp) | 覆盖默认空引用与真实空串的对称相等判断 |
| [官方 SQL suite](../../regression-test/suites/query_p0/join/test_null_safe_eq_join_string_key.groovy)及 [golden](../../regression-test/data/query_p0/join/test_null_safe_eq_join_string_key.out) | 原样移植上游提交 `e5b67e095b4fd40acd656ad25aed6bf5d8b52718` 的输入和预期 |

这项补丁修复的是已经复现的**单字符串 NULL 匹配结果错误**。目前没有复现用户六键业务查询的历史 BE crash；截图中的 `block_null_safe_equal` 是 FE 规则拦截。3.0.8 的相关 nullable Join 使用不同的 key 选择路径，因此没有把这个新版本补丁机械回补到 3.0.8。

以上原版发行包实验均使用 ARM64 二进制；不能将其写成 x86_64 修复包通过。4.1.4 官方回归框架与 Java UDF 已用本机 jenv JDK 17.0.19 编译成功，随后连接原版包完成红测；框架编译不生成修复后的 BE。

扩展探针使用固定种子、256 行 probe、40 行常规 build、33 行全 NULL build、空 build，`batch_size=16`。七种形态分别在 RF OFF / GLOBAL BLOOM、Broadcast / Shuffle 下失败：单侧 CAST 的 INNER/LEFT、单侧 CONCAT 的 INNER/LEFT、两侧 CONCAT、全 NULL build 的 INNER/LEFT。NULL 常量、两键、非对称 Nullable、NULL 与真实空串等其他组合通过。完整范围见 [扩展探针说明](../../tools/null-safe-join/EXTENDED.md)。

扩展实验的 FE/BE 都报告 `doris-4.1.4-rc04-ad35a140c7f`；BE 前后 Alive，`LastStartTime` 不变；容器未发生 OOM 或自动重启。EXPLAIN 证明实际选择的 Join 分发与 RF 生成，尚不证明 RF 运行时到达/过滤行数，也不证明具体算子的内部块数。

本地证据位于仓库旁 `../doris-investigation-20260911/`，不提交测试数据和构建产物：

## 构建和发布状态

已准备隔离的 Linux x86_64 构建环境；不修改宿主机默认 Java 8。最终包必须来自本 fork 同一提交的 FE/BE 构建输出，并记录实际版本、编译模式、CPU 选项、依赖、源码 SHA 和包摘要。此时尚无通过验收的安装包，不能用原版 BE 配合新源码或单独编译成功的回归框架冒充修复包。

`clang-format 16` 仓库检查已通过。上游 golden 的 SHA-256 为 `275b54aa5d50469638067d8bac3abe98db00209a058090e9237df6205da01c0c`，suite 为 `4c270bbc9ce1ccc9994dcfe74d1e9a4b6ebadf5c1676d22888035447daf79014`。golden 保留上游生成格式的末尾空行，Git 默认 EOF 空白检查会提示该行；其余代码空白检查通过，未为消除提示改写预期。

生产升级仍需完整 `q_raw`、实际字段类型、代表性数据、多 BE 场景及恢复演练。现有证据能界定这项已复现缺陷，不能保证所有未来 Join/RF 问题不存在。
